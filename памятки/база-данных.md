### Таблица `users` (bot.db)

| Поле | Тип | Описание |
|---|---|---|
| chat_id | INTEGER PK | Telegram chat_id пользователя |
| user_name | TEXT | Отображаемое имя (full_name) |
| joined_at | TEXT | Дата первого /start (ISO 8601) |
| consent | INTEGER DEFAULT 0 | 1 — пользователь дал согласие на обработку данных |
| consent_at | TEXT | Дата последнего изменения consent |
| is_active | INTEGER DEFAULT 1 | 0 — бот заблокирован пользователем |
| access | TEXT DEFAULT 'pending' | Доступ по подтверждению админом: `pending` / `approved` / `denied` |

Запись создаётся при каждом `/start`. При попытке отправить сообщение заблокировавшему пользователю — `is_active` ставится в 0.

**Доступ по подтверждению (`access`).** Бот закрытый: новый пользователь после `/start` получает
`access='pending'`, и до решения админа всё, кроме `/start`, блокируется middleware-гейтом
(`AccessMiddleware`). Админу (`ADMIN_ID`) приходит заявка с кнопками **✅ Одобрить / ❌ Отклонить**
(`approve_{id}` / `deny_{id}`); ожидающие заявки можно посмотреть командой `/requests` (только админ).
Полный список со статусами и управлением — `/users` (кнопка бан/доступ на каждого), снять/вернуть
доступ напрямую — `/ban <id>` / `/unban <id>`. Бан = `access='denied'` (тот же гейт блокирует).
Админ всегда `approved` и проходит гейт без проверки.

**Меню команд разное (`set_my_commands` со scope).** Обычным пользователям — пользовательское
меню (с `/write`, без админских команд). Админу в его чате (`BotCommandScopeChat`
по `ADMIN_ID`) — отдельное меню: админские команды (`/users`, `/requests`, `/ban`, `/unban`,
`/broadcast`) наверху, без `/write` (админу некому себе писать). **Миграция:** при первом добавлении колонки
`access` все, кто уже был в базе, помечаются `approved` (grandfather) — правка не выкидывает текущих
пользователей. Новые после этого — `pending`.

### Таблица `ict_signals` (bot.db) — стратегия №6
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | Автоинкремент |
| instrument | TEXT | Код инструмента реестра |
| direction | TEXT | `long` / `short` |
| pool_price | REAL | Снятый пул ликвидности |
| entry_price / stop_loss / take_profit | REAL | Вход по рынку, стоп за манипуляцией, цель |
| bar_time | TEXT | Свеча решения (таймфрейм `ICT_TIMEFRAME`, UTC) — якорь трекинга исхода |
| sweep_time | TEXT | Свеча, снявшая ликвидность |
| gap_atr / disp_atr / risk_atr | REAL | Признаки момента: разрыв, импульс и риск в ATR |
| status | TEXT | `open` / `hit_tp` / `hit_sl` / `expired` |
| result_r | REAL | Итог в R без издержек |
| created_at / closed_at | TEXT | ISO 8601 |
| — | UNIQUE(instrument, direction, bar_time) | Дедуп по свече; второй дедуп — окно `ICT_DEDUP_MIN` |

Сигнал общий для всех подписчиков инструмента (личных настроек у стратегии нет), поэтому
`user_id` тут не нужен — в отличие от `signals`, где сигналы ложного пробоя персональные.

### Таблица `user_settings` (bot.db) — личные фильтры строгости
| Поле | Тип | Описание |
|---|---|---|
| user_id | INTEGER | Telegram ID |
| key | TEXT | Имя ключа из `config.TUNABLE` (`MAX_ENTRY_DIST_ATR` / `MAX_RISK_ATR`) |
| value | REAL | Личное значение (`0` = фильтр выключен) |
| — | UNIQUE(user_id, key) | Один ключ на пользователя |

Личные переопределения подписчика поверх общих значений. Чего тут нет — берётся из общих
настроек (`settings.json` / дефолтов). См. «Строгость отбора».

**Старые ключи остаются лежать** в этой таблице у тех, кто крутил `VOL_MULT`, `MIN_RR` и прочее
до 20 августа 2026. Вреда нет: `config.effective()` игнорирует всё, чего нет в `_DEFAULTS`.

### Таблица `trades` (bot.db) — журнал сделок
| Поле | Тип | Описание |
|---|---|---|
| id | INTEGER PK | Автоинкремент |
| user_id | INTEGER | Telegram ID владельца сделки |
| instrument | TEXT | Код инструмента движка ИЛИ символ контракта BingX (как `alerts.pair`). Старые записи с тикерами Yahoo читаются, но не ведутся |
| direction | TEXT | `long` / `short` (определяется по числам: стоп/цель относительно входа) |
| entry_price / stop_loss / take_profit | REAL | Параметры сделки (все три обязательны для трекинга) |
| status | TEXT DEFAULT 'open' | `open` / `hit_tp` / `hit_sl` / `closed` (последнее — ручное закрытие) |
| bar_time | TEXT | Момент записи (UTC ISO) — якорь для трекинга исхода по свечам |
| note | TEXT NULL | Заметка (зарезервировано) |
| opened_at / closed_at | TEXT | Даты открытия и закрытия (ISO 8601) |

Записывается свободным текстом через NL-роутер («взял золото по 2390, стоп 2380, цель 2410»).
Исход доводит `scheduler.track_trades` (каждые 5 мин) по часовым свечам BingX — и для
инструментов реестра, и для своей пары. **Журнал не истекает** (в отличие от сигналов):
`expired` от `evaluate_signal` трактуется как «ещё открыта» — сделка висит до цели/стопа/
ручного закрытия.
