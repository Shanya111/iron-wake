# Общая основа: уровни, направление, объём

Это не отдельная стратегия, а фундамент, на котором стоят все три действующие:
- уровни и их сила;
- направление;
- стакан.

## Что считается и кто этим пользуется

| что | где в коде | кто пользуется |
|---|---|---|
| уровни-фракталы: D1 окно 5, H1 окно 3 | `analyzer.find_levels` | ложный пробой, пробой уровня, `/analyze`, алерты |
| сила уровня: H1 совпал с D1 в пределах 0.1% (`LEVEL_MATCH_TOL`) | `analyzer.prioritize_levels` | пробой уровня (обязательна), ложный пробой (только приоритет) |
| таблица `levels` — пересчёт раз в час | `scheduler.run_analysis` | ложный пробой, пробой уровня |
| направление: EMA20 по 6-часовым свечам (`TREND_TF_HOURS = 6`) | `analyzer.engine_trend` | ложный пробой (фильтр), `/analyze`, пробой уровня (только записывается) |
| тренд EMA20 по дневке | `analyzer.get_trend` | только справочно в лог `run_analysis` |
| ATR за 14 свечей | `pattern_detector._atr` (`ict.atr_series` у ICT) | стопы всех стратегий |
| стакан (DOM) | `analyzer.analyze_order_book` | только `/analyze` |

> **Поправка 26.09.2026:** в старом CLAUDE.md направление ложного пробоя местами названо
> «тренд дневки». По коду с 16.09.2026 это EMA20 по 6-часовым свечам.

ICT уровни из таблицы не берёт: пулы ликвидности он ищет сам, по своим свечам (`ict.py`).

## Раздел из старого CLAUDE.md (дословно)

### Стратегия №1 — контекстный анализ (`analyzer.py`)
- `get_trend(df)` — глобальный тренд по EMA20: `up`/`down`/`sideways`.
- `find_levels(df, window, timeframe)` — пики/впадины фракталом: D1 окно 5, H1 окно 3.
- `find_liquidity_zones(df, mult)` — свечи с объёмом > среднего × `LIQUIDITY_MULT` (зоны Smart Money).
- `analyze_order_book(ob, wall_mult)` — сводка по стакану (DOM, по инструментам движка): давление
  сторон (`buyers`/`sellers`/`balance` по дисбалансу объёмов bid/ask), спред и «стены» — крупнейшие
  заявки, чей объём > медианы стороны × `WALL_MULT` (медиана, т.к. сама стена раздувает среднее).
  Запись стакана берётся по индексу — некоторые биржи отдают `[цена, объём, время]` (3 элемента),
  BingX отдаёт `[цена, объём]`. В отчёте `/analyze` стакан описан человеческим языком; при очень
  широком спреде DOM помечается недостоверным и «стены» не показываются (у тонких пар набора —
  TON 0.15%, ADA 0.29% — это штатная ситуация, у BTC и золота спред околонулевой).
  Подмешивается в `/analyze` (текст + AI-промпт); ошибка стакана не валит анализ.
- `prioritize_levels(d1, h1, tol)` — уровень H1, совпавший с D1 в пределах 0.1%, помечается
  `strong`, иначе `weak`.
